Démarrer

Ce que Mon Chai ouvre aujourd'hui à votre application, ce qui n'existe pas encore, et par où commencer.

Vous fabriquez votre propre application — un tableau de bord, une alerte d'impayés, des étiquettes, une boutique — souvent avec l'aide d'un assistant IA, et vous voulez que Mon Chai fasse le reste : la vigne, le chai, les stocks, la facturation, la DRM. Cette documentation dit exactement ce que Mon Chai vous ouvre aujourd'hui, avec des exemples qui fonctionnent tels quels.

Astuce si vous codez avec un assistant IA (Claude, ChatGPT, Cursor…) : donnez-lui l'adresse de cette page et de la page API REST v1 (ou Connecteur), et la description OpenAPI. Tout ce qu'il lui faut y est écrit : vraies adresses, vrais noms d'outils, vraies colonnes. Demandez-lui de ne rien inventer au-delà.

Ce que Mon Chai ouvre aujourd'hui

Lire vos données : le connecteur

Un serveur MCP protégé par OAuth 2.1. Votre application obtient, avec votre accord, un accès en lecture seule à une exploitation : stocks (vrac, bouteilles, lots) et factures (liste, détail, impayés, chiffre d'affaires).

Connecteur (MCP + OAuth 2.1) · Référence des outils

Lire vos données : l'API REST v1

Les mêmes données que le connecteur, par de simples requêtes GET avec une clé d'API personnelle, créée dans Administration › Connecteur IA & clés d'API. Pour un script, un tableur, un serveur : pas de navigateur, pas d'OAuth. Lecture seule.

Envoyer vos données : les imports CSV

Votre application produit un fichier CSV (cépages, appellations, parcelles, unités, entrepôts, cuvées, clients, produits, lignes de tarif) ; vous le déposez dans Mon Chai, qui le vérifie ligne à ligne avant d'écrire quoi que ce soit.

Comprendre le métier

Exploitation, parcelle, vendange, lot technique, cuvée, référence, lot commercial, document commercial, DRM : les mots de Mon Chai, pour que votre brique parle la même langue.

Modèle métier

Ce qui n'existe pas encore

Pour vous éviter de chercher (ou de laisser votre assistant inventer) :

  • pas d'écriture par programme : ni le connecteur ni l'API REST ne créent, ne modifient ou ne suppriment quoi que ce soit ; pour envoyer des données, il y a les imports CSV, déposés dans l'interface ;
  • pas de webhooks : Mon Chai ne prévient pas votre application d'un changement, c'est elle qui interroge ;
  • pas de bac à sable dédié aux développeurs.

La seule API publique est /api/v1/. Les autres adresses /api/… que vous pourriez croiser (/api/auth/……) servent l'interface de Mon Chai elle-même : elles peuvent changer sans préavis. Ce qui est à l'étude est dans la feuille de route.

Pour qui

  • Vous avez un compte Mon Chai (ou travaillez pour une exploitation qui en a un) et vous voulez brancher votre propre outil dessus.
  • L'accès se fait au nom d'une personne : celle qui clique sur « Autoriser » et choisit l'exploitation. Votre application ne voit que ce que cette personne a le droit de voir, dans cette exploitation-là.

Par où commencer

  1. Choisissez votre porte : un programme qui tourne seul → API REST v1 (une clé) ; un assistant IA ou une appli où chacun se connecte → connecteur (OAuth). Les deux pages vont jusqu'aux exemples complets.
  2. Lancez l'exemple de votre langage. Par l'API : Python ou TypeScript ; par le connecteur : Lire mes stocks depuis mon appli (Python) ou Lister mes impayés (TypeScript).
  3. Choisissez ce dont votre application a besoin dans la référence de l'API ou celle des outils.
  4. Avant de mettre en service, relisez Sécurité et bonnes pratiques.
